# 用語集

画面内の正式表記は、導入済みの機能や UI 言語によって異なる場合があります。ここでは画面説明に必要な範囲で簡潔に定義します。

| 用語 | 概要 | 主に関わる製品 |
| --- | --- | --- |
| **SevOne NMS** | ネットワーク性能監視の中核。対象を登録し、データを収集して状態を扱う。 | NMS |
| **SevOne Data Insight (DI)** | NMS のデータをレポート・ダッシュボード・分析として表示するアプリケーション。 | DI |
| **Cluster** | 複数のコンポーネント／ノードで構成する製品基盤を指す文脈の語。画面や設定によって対象範囲が異なる。 | NMS / DI |
| **Peer** | クラスタ内の個別ノードを指すために使われる語。 | NMS / DI |
| **Device** | 監視するネットワーク機器、サーバー、仮想的な対象などの単位。 | NMS |
| **Discovery** | 監視対象を検出・取り込むための機能または工程。 | NMS |
| **Object** | Device 配下で監視・集計する対象の単位。インターフェースなどが代表例。 | NMS |
| **Object Type** | Object を分類する型。収集項目や画面での扱いに関係する。 | NMS |
| **Indicator / Metric** | 状態や性能を表す測定値・指標。UI では文脈により呼び方が異なる。 | NMS / DI |
| **Plugin** | 特定の機器・プロトコル・データ種別の収集や連携を提供する拡張機能。 | 主に NMS |
| **Poll / Polling** | 監視対象に問い合わせてデータを定期的に取得すること。 | NMS |
| **Device Group / Object Group** | Device や Object を目的・組織・技術領域などでまとめる単位。表示・権限・絞り込みに使われる。 | NMS |
| **Metadata** | Device や Object に追加する分類・属性情報。レポートや検索の絞り込みに使える。 | NMS |
| **Policy** | 監視対象への収集・判定の適用方針を定義する仕組み。 | NMS |
| **Threshold** | 指標がどの値・条件になれば注意または異常として扱うかを定める基準。 | NMS |
| **Alert** | 監視状態や条件に基づく通知・事象。 | NMS / DI の表示文脈 |
| **Flow** | 通信の送受信・会話に関する情報。通信量や送信元／宛先などの分析に使う。 | NMS / DI |
| **Report** | 指定した期間・対象・変数・Widget によりデータを表示する定義またはその表示結果。 | DI |
| **Widget** | DI の Report 上に置くグラフ、表、ランキング、分析表示などの部品。 | DI |
| **Data Source** | DI がデータ参照に使う接続先・データ基盤の定義。 | DI |
| **Instant Graph** | 選択した対象・期間を素早く可視化するための DI の表示機能。 | DI |
| **Flow Explorer** | Flow を対話的に絞り込み・分析する DI の画面・機能。 | DI |
| **Tenant** | DI で利用者・データ・設定の範囲を分ける論理的な区画。 | DI |
| **Team** | DI で利用者・共有範囲を整理するグループ。利用可否は設定による。 | DI |
| **User Role / Role** | 利用者が閲覧・実行できる機能や対象範囲を制御する権限のまとまり。 | NMS / DI |
| **OOTB (Out of the Box)** | 製品導入直後から提供される標準の設定、レポート、部品など。 | 主に DI |
| **SSO / OpenID Connect** | 外部の認証基盤と連携してログインする方式。 | NMS / DI |

## 読み分けの補助

- **NMS の「対象を作る・集める・判定する」** と、**DI の「選ぶ・見せる・分析する」** を分けて考えると、画面の役割を追いやすくなります。
- **Device / Object / Indicator** は階層として現れやすい語です。画面が何を一行として並べているかを見ると、現在の粒度を判断できます。
- **Group / Metadata / Tenant / Team / Role** は、いずれも「範囲を分ける」概念ですが、用途が異なります。Group と Metadata は主に対象整理、Tenant と Team は DI の利用・共有範囲、Role は権限に関わります。
