# 全体像：NMS と Data Insight の役割

## 一言でいうと

SevOne NMS は、ネットワーク機器や関連する監視対象から情報を取り込み、何を監視するか、状態をどう判定するかを扱う中核です。SevOne Data Insight（DI）は、そのデータを使ってレポート、グラフ、表、ランキング、フロー分析として閲覧・共有する入口です。

この分け方は厳密な技術仕様ではなく、画面を説明する際の実用的な目安です。導入済みのプラグイン、権限、テナント、ライセンスによって、利用可能な画面は異なります。

## 大まかなつながり

ネットワーク機器・サービス  
↓ 収集  
SevOne NMS: Devices / Discovery → Objects・指標 → Policies・Thresholds → Alerts  
↓ データ参照  
SevOne Data Insight: Data Sources → Reports / Widgets / Explore / Flow Explorer  
↓  
利用者の閲覧・共有・運用判断

NMS は DI の可視化に必要なデータの基盤です。DI の 8.1.0 リリースノートでは、DI は NMS がレポート用に生成する情報に依存するとされ、NMS のリソース名を変更すると依存するレポートに影響し得ると説明されています。したがって、名称・対象・権限の変更は、収集だけでなく DI レポートへの影響も意識します。

## NMS で主に見るもの

| 領域 | 見る・理解する対象 | 近い画面群 |
| --- | --- | --- |
| 監視対象 | デバイス、Discovery、グループ、メタデータ | Devices / Discovery、Groups |
| 収集内容 | Object、指標、プラグイン、ポーリング | Objects / Monitoring、Plugins |
| 状態判定 | Policy、Threshold、アラート | Alerts / Rules |
| 通信観測 | Flow と通信量に関する監視 | Flow Monitoring |
| 運用基盤 | ユーザー、ロール、認証、クラスタ、統合 | Administration、Access |

NMS の画面地図は [NMS の README](nms/README.md) と [ナビゲーション](nms/navigation.md) を参照してください。

## 新規環境で意識する順序

1. **NMS の対象と収集を理解する。** どのデバイス・オブジェクトを何の目的で観測するかが、以後の表示の前提になります。
2. **NMS の状態判定を理解する。** Policy・Threshold・Alert は「いつ問題として扱うか」に関わります。
3. **DI の接続先を把握する。** DI の Data Source と、表示するデータの元となる NMS の対応を確認します。
4. **DI の標準レポートから読む。** 新規インストール後には OOTB レポートが取り込まれるため、これらを画面理解の出発点にします。
5. **ロールと閲覧範囲を確認する。** 同じ URL でも、利用者の権限でメニューやデータが異なります。

この順序は設定手順ではありません。各画面を説明する際に、なぜその画面が存在するのかを理解するための順序です。

## 閲覧と将来の変更

現在の対象は画面説明・閲覧です。ただし、将来設定する可能性に備え、各画面群のページでは変更可能な項目と影響を大まかに触れます。特に次の変更は複数画面へ波及し得ます。

- デバイス、Object、グループ、メタデータの変更: 収集対象、絞り込み、レポート変数に影響
- Policy、Threshold、Alert の変更: 状態判定、通知、運用フローに影響
- NMS のリソース名の変更: DI の名前に依存するレポートに影響する可能性
- ロール、ユーザー、テナント、Team の変更: 表示できるメニュー・データ・共有範囲に影響
- Data Source の変更: DI で閲覧できるデータ基盤に影響

変更を実行する局面では、画面説明用の本書だけで判断せず、8.1.0 の公式ガイドと実環境の権限・変更管理手順を確認してください。
