# 基本概念とデータの流れ

## 収集から可視化まで

```text
ネットワーク機器／サーバー／フロー送信元
  → NMS デバイス → プラグインでのポーリングまたは受信
  → オブジェクトとインジケーター（メトリック）
  → グループ／メタデータで整理
  → ポリシー・しきい値で評価 → アラート、または DI のレポート・分析
```

## 用語

|用語|意味|主な画面|
|---|---|---|
|デバイス|NMS が監視するIP到達可能な対象。|デバイス・マネージャー|
|プラグイン|SNMP、ICMP、WMIなどの取得方法。|デバイス詳細、管理|
|オブジェクト|インターフェース、CPU、ファンなどの監視単位。|オブジェクト・マネージャー|
|インジケーター|オブジェクトから得る数値や状態。|オブジェクト詳細|
|グループ|複数デバイス／オブジェクトを束ねる論理的な対象。|グループ・マネージャー|
|メタデータ|場所、担当、サービスなどの属性。|メタデータ|
|ポリシー|グループに監視条件と通知を適用する定義。|ポリシー・ブラウザー|
|しきい値|メトリックが異常とみなされる条件。|しきい値ブラウザー|
|アラート|しきい値違反、トラップ等から生じる運用イベント。|アラート|
|ピア|NMSクラスタを構成するアプライアンス。|クラスター・マネージャー|

## NMS と DI の境界

NMS は監視データの収集と異常判定、DI はデータを用いたレポート／ダッシュボード／探索の基盤です。DI が参照する NMS リソース名を安易に変更すると既存のDI資産に影響することがあるため、運用開始後の名称変更は影響を確認してから行います。
